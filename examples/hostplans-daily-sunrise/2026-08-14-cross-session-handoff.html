Use the message as an interrupt, not the artifact

A cross-session message should identify the canonical plan, current state, fresh delta, next action, and stop condition. The receiver opens the plan, verifies the workspace and authority, then acknowledges one action before editing.

The message routes attention

Original Hostplan diagram. Explicit dimensions reserve the final layout.

The five-line envelope

Pointer

Canonical plan URL or id.

State

Status and verified UTC time.

Delta

Only what changed.

Next

One scoped action.

Stop

The human decision gate.

Copyable message

HANDOFF
Plan: https://plans.host-plan.com/p/<id>
State: blocked · verified 2026-08-14T11:40:00Z
Delta: CI is green; one review thread remains open.
Next: read the plan, verify the PR head, then answer that thread.
Stop: ask before changing scope, dependencies, or deployment state.

Receiver protocol

  1. Resolve the pointer. Confirm the plan belongs to the intended project and branch.
  2. Re-observe state. Compare the checkpoint with the workspace, PR, and external systems.
  3. Revalidate authority. Confirm the receiving session may use the named tools and data.
  4. Acknowledge one action. Reply with the verified checkpoint before editing.
